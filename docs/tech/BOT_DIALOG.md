# Архитектура диалогов VK-бота

## Роли: кто может что делать

Перед сценарием бот выясняет, **известен ли человек в системе** и **какая у него роль**. В API это значения роли профиля (`member`, `manager`, `admin`); ниже — те же роли в пользовательских терминах.

| Что ответила система | Кто это для пользователя |
|----------------------|---------------------------|
| Не найден | Ещё не зарегистрирован |
| Завснар | Ответственный за склад и заявки |
| Юзер | Обычный участник |
| Админ | Администратор (расширенные права, как у завснара на складе) |

**Только завснар или администратор** могут добавлять и править позиции на складе. **Просмотр склада по названию** доступен любому с профилем. **Оформить выдачу, сдать снаряжение или работать с документом** могут участник, завснар и администратор — если профиль уже создан.

## 1. Точки входа (команды, кнопки, старт)

Отдельная картинка на каждый тип входа: команда или кнопка в меню.

### `/start`

```mermaid
flowchart TB
  subgraph start_cmd["Старт диалога"]
    S0([Пользователь нажал /start])
    S0 --> C0{Уже есть профиль?\nКакая роль?}
    C0 -->|ещё нет в системе| Sreg["Нет учётной записи:\nпереход на сайт (вход/регистрация),\nзатем ввод кода привязки здесь"]
    C0 -->|завснар| Smgr["Коротко представляемся как завснар,\nпоказываем нужные кнопки"]
    C0 -->|админ| Sadm["Коротко представляемся как администратор,\nпоказываем нужные кнопки"]
    C0 -->|участник| Susr["Коротко представляемся как участник,\nпоказываем нужные кнопки"]
  end
```

### Получить снаряжение

```mermaid
flowchart TB
  subgraph gear_in["Получить снаряжение"]
    Gin0([Команда или кнопка\n«Получить снаряжение»])
    Gin0 --> Gu{Профиль уже есть?}
    Gu -->|нет| Gstop[Сценарий не продолжаем]
    Gu -->|да| Ginfo[Напоминаем про взнос\nи документ, если нужно]
    Ginfo --> Gstep["Дальше — пошаговый выбор позиций\nи согласование с завснаром"]
  end
```

### Сдать снаряжение

```mermaid
flowchart TB
  subgraph hand_in["Сдать снаряжение"]
    Hin0([Команда или кнопка\n«Сдать снаряжение»])
    Hin0 --> Hu{Профиль уже есть?}
    Hu -->|нет| Hstop[Сценарий не продолжаем]
    Hu -->|да| Hapi{Есть ли у человека\nчто сдавать?}
    Hapi -->|ошибка или список пустой| Hclr[Объясняем и выходим из сценария]
    Hapi -->|есть позиции в аренде| Hlist[Показываем список и как выбрать позиции для сдачи]
    Hlist --> Hstep["Дальше — выбор позиций и завснара,\nзатем заявка"]
  end
```

### Склад (просмотр позиций)

```mermaid
flowchart TB
  subgraph list_in["Склад (просмотр позиций)"]
    Lin0([Команда или кнопка\n«Посмотреть снаряжение на складе»])
    Lin0 --> Lchk{Профиль уже есть?}
    Lchk -->|нет| Lstop[Сценарий не продолжаем]
    Lchk -->|да| Lstep["Спрашиваем название позиции,\nпоказываем что нашлось"]
  end
```

### Завснар или администратор

```mermaid
flowchart TB
  subgraph mgr_in["Завснар или администратор"]
    M1([Команда «добавить на склад»]) --> M1s["Пошагово вводим новую позицию"]
    M2([Команда «обновить склад»]) --> M2s["Пошагово меняем существующую позицию"]
  end
```

### Изменить тип залогового документа

```mermaid
flowchart TB
  subgraph doc_in["Документ"]
    D0([Команда /document])
    D0 --> Du{Профиль уже есть?}
    Du -->|нет| Dstop[Сценарий не продолжаем]
    Du -->|да| Ddoc{В профиле сейчас\nнет сохранённого документа?}
    Ddoc -->|да, сдать новый| Dnew["Спрашиваем название документа,\nпотом завснара для подтверждения"]
    Ddoc -->|нет, документ уже есть| Dret["Хотят вернуть документ:\nвыбираем завснара из списка"]
  end
```

### Без шага диалога

```mermaid
flowchart TB
  subgraph passive["Одно сообщение — один ответ"]
    P1([Мои аренды]) --> P1list[Показываем что у человека на руках\nили что пошло не так]
    P2([Взнос]) --> P2txt[Текст с инструкцией по взносу]
    P3([Обратная связь]) --> P3txt[Ссылки на форму и контакты]
  end
```

## 2. Регистрация и привязка мессенджера к аккаунту

Учётная запись создаётся или подтверждается **на сайте** (единая форма входа и регистрации). Бот участвует только на шаге **проверки кода**, который пользователь получает после успешного действия на сайте и вводит в чате, чтобы связать VK-id с уже существующим профилем.

```mermaid
stateDiagram-v2
  direction TB

  [*] --> to_site: В боте известно,\nчто аккаунт ещё не привязан к этому чату
  to_site --> on_site: Бот даёт ссылку,\nпользователь открывает сайт
  on_site --> issued_code: На сайте единая форма — вход или регистрация\nПосле успеха пользователь видит код привязки
  issued_code --> enter_code: Возврат в чат,\nотправка кода боту
  enter_code --> enter_code: Код неверен или истёк,\nпросим повторить или снова открыть сайт
  enter_code --> linked: Код принят,\nпрофиль привязан к мессенджеру
  linked --> [*]: Дальше работаем как с известным пользователем\nпо роли из профиля

  note right of on_site
    Сайт — единственное место ввода логина, пароля
    и данных регистрации. Бот их не запрашивает.
  end note
```

## 3. Получить снаряжение (пошагово)

В основном линейная цепочка; после подтверждения выбора можно снова **продолжить подбор** по названию.

```mermaid
stateDiagram-v2
  direction TB

  state "Ищем позиции по названию" as pick_search
  state "Выбираем что и сколько" as pick_qty
  state "Подтверждаем корзину" as confirm_pick
  state "Указываем мероприятие" as pick_event
  state "Выбираем завснара" as pick_mgr
  state "Срок возврата" as return_when
  state "Комментарий (по желанию)" as note_optional
  state "Ждём решение завснара" as sent_pending

  [*] --> pick_search: Команда или кнопка «Получить…»
  pick_search --> pick_search: Ничего не нашли или сбой —\nостаёмся здесь
  pick_search --> pick_qty: Есть совпадения по складу
  pick_qty --> pick_qty: Ошибка ввода
  pick_qty --> confirm_pick: Количества согласованы,\nпоказываем итог и кнопки
  confirm_pick --> pick_search: «Продолжить выбор»
  confirm_pick --> pick_event: «Выбрать мероприятие»
  pick_event --> pick_mgr: Текст мероприятия и список завснаров
  pick_mgr --> pick_mgr: Завснар не распознан
  pick_mgr --> return_when: Завснар выбран
  return_when --> return_when: Дата или срок не подходят
  return_when --> note_optional: Срок выбран
  note_optional --> sent_pending: Текст или «Пропустить» —\nзаявка участнику и завснару с Принять/Отклонить
  sent_pending --> [*]: Сценарий закрыт, черновик очищен
```

## 4. Сдать снаряжение

```mermaid
stateDiagram-v2
  direction TB

  state "Выбираем что сдаём" as choose_lines
  state "Выбираем завснара (кому отдаём)" as handover_pick_manager
  state "Заявка на сдачу у завснара" as handover_request_sent

  [*] --> choose_lines: Команда «Сдать…» и список того,\nчто на руках, загрузился
  choose_lines --> choose_lines: Неверный ввод или пустой выбор
  choose_lines --> handover_pick_manager: «Сдать всё» или строки выбраны —\nсписок завснаров
  handover_pick_manager --> handover_pick_manager: Завснар не распознан
  handover_pick_manager --> handover_request_sent: Завснар выбран —\nзаявка с Принять/Отклонить
  handover_request_sent --> [*]: Сценарий закрыт, черновик очищен
```

## 5. Завснар: новая позиция на складе

```mermaid
stateDiagram-v2
  direction TB

  state "Название позиции" as ask_title
  state "Всего единиц на складе" as ask_total_units
  state "Свободно для выдачи" as ask_available_units
  state "Описание или пропуск" as ask_description

  [*] --> ask_title: Шаг 1
  ask_title --> ask_total_units: Название введено
  ask_total_units --> ask_available_units: Количество «всего» введено
  ask_available_units --> ask_description: Количество «свободно» введено
  ask_description --> [*]: Ввод описания или «Пропустить»,\nпозиция сохранена,\nсценарий закрыт
```

## 6. Завснар: правка существующей позиции

```mermaid
stateDiagram-v2
  direction TB

  state "Поиск позиции на складе" as edit_find
  state "Выбор строки из списка" as edit_pick
  state "Ввод нового названия" as edit_title
  state "Описание или пропуск" as edit_note
  state "Новое общее количество" as edit_total_units

  [*] --> edit_find: Команда «обновить склад»
  edit_find --> edit_find: Ошибка или поиск ничего не дал
  edit_find --> edit_pick: Показали список, выбираем номер строки
  edit_pick --> edit_pick: Ввели не номер из списка
  edit_pick --> edit_title: Строка выбрана
  edit_title --> edit_note: Новое название введено
  edit_note --> edit_total_units: Описание или «Пропустить»
  edit_total_units --> edit_total_units: Ожидали число,\nне распознали общее количество
  edit_total_units --> [*]: Оба числа введены,\nизменения сохранены,\nсценарий закрыт
```

## 7. Поиск и просмотр снаряжения по названию

Доступен любому с профилем: участнику, завснару или администратору.

```mermaid
stateDiagram-v2
  direction LR

  state "Запрос названия для поиска" as lookup_name

  [*] --> lookup_name: Команда или кнопка просмотра склада
  lookup_name --> lookup_name: Сбой или по запросу пусто
  lookup_name --> [*]: Показали найденное,\nотдельный сценарий не ведём дальше
```

## 8. Изменить статус документа: сдать, изменить тип, получить

```mermaid
stateDiagram-v2
  direction TB

  state "Название документа" as doc_title
  state "У кого подтвердить изменение документа" as handin_pick_mgr

  [*] --> doc_title: Документ в профиле ещё не записан
  doc_title --> handin_pick_mgr: Название введено,\nпоказываем завснаров
  handin_pick_mgr --> handin_pick_mgr: Завснар не распознан
  handin_pick_mgr --> [*]: Заявка на изменение документа у завснара,\nдиалог сброшен

  [*] --> handin_pick_mgr: Документ в профиле уже есть —\nрежим «вернуть»
```

## 9. Флоу обработки заявок пользователя

### Последовательность

```mermaid
sequenceDiagram
  participant U as Участник
  participant B as Бот
  participant Z as Завснар
  participant S as Сервер

  U->>B: Заявка оформлена в диалоге
  B->>Z: Текст заявки + кнопки Принять / Отклонить
  Z->>B: Нажата кнопка

  alt Отклонить
    B->>U: Запрос отклонён
  else Принять
    B->>S: Выполнить операцию по типу заявки
    S-->>B: Результат или ошибка
    B->>U: Итог для участника
    B->>Z: Итог для завснара
  end

  B->>B: Кнопки под сообщением убраны
```
